## 三、本轮新证据（进一步强化 C1 修复的可行性）

以下均为本轮新增核验，此前三份文档未记载：

1. **目标 ImmortalWrt 内核实为 6.18**（`target/linux/mediatek/Makefile`：`KERNEL_PATCHVER:=6.18`）。此前文档只验证了原厂 6.12。
   - 6.18 `i2c-mt65xx.c`：`I2C_M_NOSTART` 处理 **0 处**（与 6.12 相同）→ 流中重复从地址，芯片地址匹配器容忍（rtlgsw 真机已证）。
   - 6.18 `i2c-dev.c`：8192 双路径限制**不变**。
2. **`mt7987.dtsi` 的 `i2c0: i2c@11003000` 实际匹配 `mt7981_compat`，无任何 quirk 限制**——这是本轮最重要的新证据：
   - dtsi compatible = `"mediatek,mt7988-i2c", "mediatek,mt7981-i2c"`；
   - 6.18 主线 `mtk_i2c_of_match` **无 mt7988 条目** → 回退匹配 `mediatek,mt7981-i2c` → `mt7981_compat`；
   - `mt7981_compat` **没有 `.quirks` 字段**（对比：`mt6577_compat` 挂了 `max_num_msgs=1 / max_write_len=255` 的 quirk，`mt7622_compat` 挂了 `max_num_msgs=255`）→ **i2c-core 的 quirk 检查不会拒绝 write_bulk 的 3 条 8192 字节消息**；
   - `auto_restart = 1`（消息间 repeated start；其与 NOSTART 语义的矛盾由芯片地址匹配器消化——rtlgsw 在原厂真机即此形态）。
   - 换言之：**若设备树匹配到的是带 quirk 的 compatible，C1 的实现会被内核直接拒绝**；本轮确认实际匹配落在无 quirk 的 mt7981_compat 上，硬件路径畅通。
3. **mt65xx 驱动传输全程 DMA，无长度阈值**：
   - `mtk_i2c_transfer()` 内注释 `/* always use DMA mode. */`——所有消息无条件走 AP-DMA，不存在"FIFO 模式只支持小消息"的切换边界；
   - `TRANSFER_LEN` 为 16 位寄存器写入（`msgs->len` 本身是 u16），8192 远在范围内；DMA 侧 `TX_LEN` 为 32 位寄存器；
   - `mt7981_compat.max_dma_support = 33`（33 位 DMA 地址）；
   - `i2c_get_dma_safe_msg_buf()` 会对来自用户态的 buffer 做 bounce copy，无对齐/映射风险。
   - 结论：**8192 字节大消息在目标平台硬件路径无障碍**（rtlgsw 真机工作为直接证据，本条为源码级补充证据）。

## 五、C1 残余风险与上板验证清单

C1 修复在源码/文档/宿主测试三层已闭环，剩余风险只在真机行为：

- **NOSTART 不被 mtk 驱动支持**（6.12/6.18 均 0 处处理）→ 续传消息会重复发从地址；芯片可容忍（rtlgsw 出厂形态即如此）。代码已在此场景记 debug 日志。
- **quirk 路径**：本轮已确认匹配 mt7981_compat（无 quirk）；若未来换板/改 dts，需重新确认 compatible 落点。

上板验证清单（按依赖顺序）：

1. `i2cdetect -y 0` 确认 0x20 / 0x21 双地址应答；
2. 读 `0xE8` 确认镜像选择分支；
3. 触发固件下载（init.d 启动），观察 debug 日志中的 NOSTART 提示与 0xEC bit5 校验结果；
4. 下载后读 `0x30–0x33` 确认功率读数非 0（验证 10ms 延时足够，不足则按 50ms 放宽——单行改动）；
5. **C3 端口映射实测**（7 口反序 vs 8 通道恒等）：逐口插 PD 设备对照 Web 显示定性；定性后同步 `port_map` / `ports` / `overview.js` / 日志命名 / **E2 的 lan 编号上限**；
6. 端口 disable/enable（UCI disabled_ports）、供电优先级行为；
7. 掉电重启验证 SRAM 固件丢失 → init.d 自动重新下载。

## 六、结论

1. **修复轮全部 8 处修改确认到位，未发现回归，未发现新的功能性 bug。**
2. 本轮新增三项关键证据（目标内核 6.18、mt7981_compat 无 quirk、mt65xx 全程 DMA）**进一步强化了 C1 修复在目标平台上的可行性**——其中 mt7981_compat 无 quirk 是此前未验证的潜在否决点，本轮排除。
3. 新发现 3 项（E1/E2/E3）均为低危或前瞻性问题，其中 E2 与 C3 实测强关联，建议在 C3 定性时一并处理；E1/E3 可择机处理。
4. 主要风险仍集中在 C3（端口映射输入矛盾）——按用户决议保留，待上板实测定性。
