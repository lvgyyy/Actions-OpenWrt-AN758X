## 一、目标与约束

原有 `luci-app-tmi-poe` 只支持小米 BE3600 Pro 有线版（P5 → TMI7604R，P8 → TMI7608R），寄存器操作、I2C 节点、板级参数全部硬编码在 `tmi.c` / `main.c` 里。本次要求在不改动 Web 界面结构的前提下，把 RTL8238B PSE 也接进来。

三条设计约束：

1. **Web 界面尽量不变** —— 只加一行板表，UI 结构、字段、翻译全部复用。
2. **不破坏 TMI 现有行为** —— TMI 路径做回归测试，寄存器级行为必须逐字节不变。
3. **开箱即用** —— RTL8238B 固件在 SRAM 里、掉电即丢，守护进程必须自己完成下载，不能依赖厂商 `rtl8373n.ko`。

## 二、整体方案：引入芯片后端抽象层

核心改动是把原来「板 → 寄存器」的一层拆成「板 → 芯片后端 → 寄存器」：

```
main.c          传输层（I2C 适配器、GPIO、UCI、日志）
  └─ tmi.c      板表 + 分发封装 tmi_initialize()/tmi_read_status()/...
       ├─ poe_chip_tmi7608     （原 TMI7604R / TMI7608R 逻辑，原样下沉）
       └─ poe_chip_rtl8238b    （新增）
```

`struct tmi_chip` 操作集定义在 `src/tmi.h`：

```c
struct tmi_chip {
	int (*initialize)(...);
	int (*set_policy)(...);
	int (*disable)(...);
	int (*verify_policy)(...);
	int (*check_policy_status)(...);
	int (*read_status)(...);
	int (*poll_status)(...);
	bool hardware_budget;   /* 芯片是否自己强制预算 */
};
```

`struct tmi_board` 扩充的字段：

| 字段 | 作用 | TMI P5/P8 | RTL8238B |
|---|---|---|---|
| `i2c_node` | 设备树 I2C 控制器路径 | `soc@0/i2c@78b5000` | `soc/i2c@11003000`（待确认） |
| `address` | 首个 I2C 地址 | 0x50 / 0x70 | 0x20 |
| `addresses` | 连续地址数量（新增） | 1 | **2**（0x20 + 0x21） |
| `channels` / `ports` | 通道数 / 网口数 | 4/4、8/7 | 8 / 7 |
| `max_budget_mw` | 预算上限 | 60000 / 105000 | 90000 |
| `reset_gpio` | 是否接了复位线（新增） | true | **false** |
| `port_map[]` | LAN → PSE 通道 | `{2,1,4,3,…}` | `{7,6,5,4,3,2,1}` |
| `chip_ops` | 后端指针（新增） | `&poe_chip_tmi7608` | `&poe_chip_rtl8238b` |

`struct tmi_io` 的两个变化：

- `read` / `write` 增加 `address` 参数（RTL8238B 有两颗芯片，同一寄存器号要送到不同地址）
- 新增 `write_bulk(ctx, address, reg, data, len)`，供固件分块下载使用

`struct tmi_status` 新增 `input_valid` 与 `power_mw[]`，用于表达「芯片没有输入电压寄存器」和「只算得出功率」。

## 三、RTL8238B 后端实现（`src/rtl8238b.c`，451 行）

### 3.1 固件下载（最容易踩坑的部分）

RTL8238B 从 SRAM 执行，每次上电都要重新灌固件，否则 `0x30–0x33` 遥测寄存器全为 0。时序是按 `rtlgsw_disasm.txt` 重新核对过的，比早期文档更准确：

1. 读 `0xEC` bit5 —— 已置位说明固件还在（热重启），直接跳过
2. 读 `0xE8` 取设备 ID —— **每颗芯片各自读各自的 ID，各自选镜像**（ID==2 用小镜像，其余用大镜像）
3. 写 `0xEC = 0x03`
4. 回读 `0xEC`：若 bit2（download mode）未置位 → 写 `0x1A = 0x3F`，延时 10ms，再写 `0xEC = 0x03`
5. 写 `0xF4` 数据流 → **整个镜像一次 `I2C_RDWR`**（见下）
6. 逐颗校验 `0xEC` bit5

**关键修正（审计轮重写 `write_bulk`）**：芯片把整个镜像当作一条从 `0xF4` 开始的不间断字节流消费。`write_bulk` 现在按厂商 rtlgsw（`0x40bbcc`）逐指令还原的格式构造：

| 消息 | 内容 | flags | 长度上限 |
|---|---|---|---|
| 第 1 条 | `[0xF4, data…]` | `I2C_M_IGNORE_NAK` (0x1000) | 8192（数据 8191） |
| 续传 | 纯数据 | `I2C_M_IGNORE_NAK \| I2C_M_NOSTART` (0x5000) | 8192 |

分块依据是 i2c-dev 对单条 `len > 8192` 返回 `-EINVAL`；原 `pse_src/rtl-poe.c` 一次性写 21164 字节会被内核拒绝（且 rtl-poe.c 是本项目早期稿，非原厂代码）。此前实现把镜像拆成多次独立传输（块间 STOP、每块重复 `0xF4`），会交给芯片一条被截断的流——这是审计出的最高危问题，已按上表重写，并用宿主测试逐字段断言（见 §五）。

主线 mtk 驱动（含原厂 6.12 内核）不处理 `I2C_M_NOSTART`，续传消息会重复发送从地址；rtlgsw 在原厂内核上即此形态且工作正常，证明芯片地址匹配器会消费这些字节。适配器缺 `I2C_FUNC_NOSTART` 时记 debug 日志，便于是板定位。

固件 blob 已内嵌进包：`src/rtl8238b_fw.h`，`rtl8238b_fw_big[]` 21164 B、`rtl8238b_fw_small[]` 8028 B。

### 3.2 端口控制

- 寄存器 `0x12`，**每通道 2 bit**（0b00=关，0b11=开），一个字节管 4 个通道
- 0x20 管通道 0–3，0x21 管通道 4–7
- `port_ctrl_byte()` 把软件侧的 8 bit mask 打包成两个 `0x12` 字节
- 初始化顺序沿用厂商探测序列（逐颗）：`0x01 = 0x00` → `0x12 = 0x00` → 延时 → `0x12 = 0xFF`，随后立刻应用用户策略

### 3.3 遥测与功率

每通道读 `0x30 + 4*offset`（电压低字节）、`0x31 + 4*offset`（电压高字节）、`0x33 + 4*offset`（电流），其中 `offset = channel % 4`。

功率公式与厂商代码逐字节一致：

```
power_mW = ((volt_word * 250) >> 13) * ((current >> 1) & 0x3f)
```

电压/电流的标度未文档化，因此**只发布 mW 结果**，`voltage_mv[]` / `current_ma[]` 不填实测值，原始 ADC 计数保留在 `current_raw[]` 与 debug 日志里。芯片能力标志 `analog_scaled = false` 让文本状态输出显示 `voltage-mv=unavailable current-ma=unavailable power-mw=…`，避免把 0 误读为实测值；TMI 侧（`analog_scaled = true`）输出格式不变。

### 3.4 三个「芯片没有」的字段 —— 保守处理

| 缺失能力 | 处理 |
|---|---|
| 无输入电压寄存器 | `input_valid = false`，守护进程跳过 44–57V 供电检查；JSON 输出 `"input_mv":null` |
| 无 power-good 状态 | `powered = good = (通道已使能 && 实测功率 > 0)`。这样「开了口但没接设备」显示"未供电"而不是"故障" |
| 无可写预算寄存器 | `hardware_budget = false`：预算只做软件监控告警，改预算**不再 cycle 端口** |

另外：芯片自主完成 detect/classify 且不暴露结果，因此 `detect`/`classify` 报告的是「已使能通道」，用于区分"等待设备"和"已禁用"；`class4plus` 对 RTL8238B 无意义，代码直接忽略。

   - 改完同步改 `overview.js` 的 `boardDefaults` 键名

2. **板级 DTS 需补齐**：把 I2C 节点拉出来、确认 PSE 挂在 0x20/0x21。

3. **端口映射待上板实测**：7 口反序（当前实现，依据 `rtl-poe.c`）与原厂 Web 逆向的 8 通道（WAN + LAN2–LAN8）互相矛盾，`pseinfo` 里 `pse1` 还默认关闭。实测方法：关一个口，看哪个网口掉电。

4. **Web 暂不显示每口功率**：原厂界面有，本次按要求未改界面，功率只进 debug 日志。若要显示需新增 UI 字段。

5. **预算告警为纯软件**：RTL8238B 无可写预算寄存器，超预算只写日志不会主动断口。若需要硬保护，得在守护进程里主动关通道。

6. **交叉编译与真机验证**尚未进行（工作区里没有可用的 aarch64 工具链）。真机首要观察点：启动日志里固件下载是否通过 `0xEC` bit5 校验；若失败，开 debug 看 `I2C_FUNC_NOSTART` 提示与 `channel=… volt-word=… power-mw=…` 逐口读数。
